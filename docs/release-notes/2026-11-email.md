# Resend email integration

## Email sign-in follow-up

Browser sign-in now uses email and password. Account and first-admin creation
generate stable handles when omitted, and the user/classroom forms no longer ask
for a separate username. Recovery returns to email sign-in. Real email changes
revoke sessions and invalidate prior codes; the normalized email uniqueness
migration `20261112_0021` refuses collisions without changing account records.
Legacy username API clients remain supported and share the account's lockout.
An email-shaped handle cannot shadow a different account's email.

This alpha release adds optional Resend email with encrypted configuration,
durable retries and provider idempotency, signed delivery/receiving callbacks,
account invitations, single-use password recovery, password-change security
notices, optional lab/operation notices, and an administrator support inbox with
manual replies. It does not add mailbox hosting, automatic replies, attachment
execution, or automatic classroom enrollment.

The additive migration advances the single head to `20261112_0020`. Operational
configuration remains in PostgreSQL; the existing encryption key must be
preserved. All email features remain disabled on upgrade until configured.
Read the [configuration and rollback procedure](../operations/email.md).

Validation includes Linux backend tests, synthetic browser viewport/state/role
checks, PostgreSQL migration replay and schema comparison, and concurrent
recovery-code redemption. Live provider qualification must be recorded for the
specific deployment and is distinct from synthetic validation.

The frontend build tool advances to Vite 8.2.6 and the Axios transitive
`follow-redirects` dependency to 1.16.3 because the prior lockfile failed the
required dependency audit. These targeted security patches preserve the current
API base, framework, and application workflow.
